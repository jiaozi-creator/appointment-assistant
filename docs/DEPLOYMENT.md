# 部署与生产准备（操作清单，不代表已验收上线）

## 部署拓扑

当前实现：**一个或多个 Node.js 进程 + 一个共享 PostgreSQL 数据库 + Vue 静态构建**。数据库包含所有商户，以 `merchant_id` 在服务端隔离。适合受控试点；数据库本身仍是单实例，不是多主复制。

建议：域名解析 → HTTPS 反向代理（示例 `deploy/Caddyfile.example`）→ API 容器 `127.0.0.1:3001` → PostgreSQL。严禁直接公网暴露 HTTP 3001 端口和数据库端口。

## 部署前必须完成

1. 正式域名、证书、DNS、目标市场备案与经营主体/隐私政策审查。未落实前仅使用虚拟资料测试。
2. 用密码管理器生成**不同**的16位以上管理员随机密码。设置 `INIT_PLATFORM_EMAIL`、`INIT_PLATFORM_PASSWORD`。不要在生产创建演示商家，因此**不填写** `INIT_OWNER_*`。这些 bootstrap 环境变量只在首次初始化相应账号时生效，**不能作为密码重置机制**。
3. 准备HTTPS反向代理；`ALLOWED_ORIGIN=https://your-domain.example` 和 `COOKIE_SECURE=1`，数据库卷有持久化、非公开访问权限。
4. 测试备份、恢复、数据清理，建立明确的保留期限、联系删除流程，按适用法律完善隐私告知与委托处理关系。
5. 对输入限流、反滥用、敏感字段安全及访问控制开展独立安全审计。当前限流存在进程内内存，不跨多实例，也不提供验证码。
6. 确认邮件/人工邀请流程：平台**不会自动发邮件**，生成的邀请链接仅在批准/重新签发时返回一次，需要管理员安全地转交申请人；首次开通链接有效72小时，员工邀请48小时。

## Docker 启动示例

在仓库根目录下，设置 `ALLOWED_ORIGIN`、`INIT_PLATFORM_EMAIL`、`INIT_PLATFORM_PASSWORD` 环境变量后运行：

```bash
docker compose -f deploy/docker-compose.yml up -d --build
curl http://127.0.0.1:3001/api/health
```

然后由独立 Caddy/Nginx 进程启用公网HTTPS并代理到回环地址。示例配置需要替换为真实域名，域名和证书部署未由项目代码自动完成。

## 数据迁移

当前库结构在 `server/migrations-pg/001_postgres.sql`。启动时写入 `schema_migrations`，同一版本只执行一次。`server/migrations/` 里的 SQLite 文件不再运行。**真实数据升级前必须备份并在副本演练**。

持久化已经是 PostgreSQL。应用层仍按 `merchant_id` 校验，不依赖数据库行级策略。旧 SQLite 文件不会自动导入。

## 备份与恢复

备份使用 `pg_dump`：

```bash
DATABASE_URL=postgres://appointment:appointment@127.0.0.1:5432/appointment node scripts/backup.js
```

工具写出 custom 格式备份，权限设为 600。**必须将备份加密复制到另一存储介质**，并定期测试恢复。不能只备份到同一个数据库卷。

恢复演练：停止服务、妥善保留现有库及 WAL/SHM 文件、恢复备份至数据文件、确保未混入旧 WAL、重启并核对迁移和业务数据。任何真实恢复都应有审批及记录。
